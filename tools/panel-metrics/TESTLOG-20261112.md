## 2. 根因备忘

内置 "Pushed value" 控件（`type:"push"`）的颜色**只由 payload 的 `level` 字段驱动**
（ok=绿 / warn=橙 / error=红），gauge 的 `max` 只定义满量程。此前 `gpu_power` 恒绿
= 脚本推它时从来没带 `level`；`strata_ctx` 会变色就是因为它带了。

## 3. 充电与换口实测（本轮顺带拿到的硬数据）

- **65% 复充首次触发**：13:46:36 `charging_enabled 0 -> 1 (读回 1)`，此后在爬
  （13:39 起 2535mAh 级别 → 69%，+~270mA ≈ 6%/h）。"复充能否爬回 80"待 80 时盖棺。
- **旧假设"该口按 USB2 只给 500mA"作废**：手机 `input_current_max=1700000`（**1.7A**）
  且正在顶格用；复充时 3T 亮屏系统负载吃掉 ~1.4A，剩 ~250-270mA 进电池。
- **换口实测三口同档**（连换连测，每口读 `input_current_max` + 电池净进流）：
  root `1-12`（原口）→ 前置 ASM107x hub `1-10.1` → 背板直连 `1-7`，
  三口全部 1.7A / 246-269mA，**与物理口无关**——Lineage 对"标准 PC USB 主机"的
  固定检测档；3T 无 PD/QC 握手，换任何口都给不出更多。**换口退路排除**。
  真正伤电池的是停充+亮屏时电池补差放电（~20%/h 寄生循环）；免费杠杆=面板降亮度。
- 读数注意：`charge_counter` 是"当前剩余量"不是累计库仑计（充电中被 OCV 修正拽跳），
  `capacity` 在换口/断电瞬间会跳 1-2 格（gauge 修正，非真掉电）；趋势以心跳日志为准。

## 4. ppps 逐口断电能力实测（手机现挂 `1-10.1`）

```
sudo uhubctl -l 1-10 -p 1 -a 0   # 断（同物理口 SS/HS 两层 2-8/1-10 联动 off）
sudo uhubctl -l 1-10 -p 1 -a 1   # 回
```
14:15 演示时间线（服务器/手机两侧对表，手机钟此时慢 52s）：
断电 → 内核 `usb 1-10.1: USB disconnect`、adb 从设备列表消失、手机 0.2s 内
`plug edge: plugged=false` + `USB data link -> false`；
回电 → 重新枚举、adb 回、`usb_online=1`、充电续（+265mA）、agent 看门狗自动重建
reverse（`UsbFfs tcp:8765`）、`via=USB` 回正。
**断电全程面板不熄屏、数据经 Wi-Fi 续流**——agent 在线 ⇒ `hostAlive` 成立，
"断充电 ≠ 主机关机"的判据语义在真断电场景实锤。root 直连口（1-7/1-12）不在
uhubctl 可控清单；需要"软件拔线"做测试就用这条命令，不必动手。

## 5. 对表新坑

本轮手机对服务器钟差从 +0.49s 变成 **−52s**（3T 钟漂 + 断电期间 NTP 重校）。
